# Game Vision Document

> **Purpose:** Establish the creative vision, identity, intended player experience, and high-level direction of a game. This document communicates what the game aims to achieve and provides a foundation for major design, production, and scope decisions.
>
> **Usage:** Copy this template into the game's project documentation directory and customize it. Keep the vision focused on the essential identity of the game. Detailed mechanics, systems, content, and implementation requirements belong in their respective documents.

## 1.1 Document Purpose

This document defines the creative vision of **[Game Name]**.

It establishes:

- The fundamental idea behind the game.
- The experience the game aims to deliver.
- The intended audience.
- The game's identity and distinguishing characteristics.
- The emotional and thematic direction.
- The creative boundaries of the project.
- The high-level goals that guide development.

The vision should help the project maintain a coherent identity as design decisions, features, and content evolve.

## 1.2 Document Scope

This document defines the high-level creative direction of the game.

It does not replace:

- The Game Design Document, which describes the overall game design.
- The Core Pillars document, which defines the essential design commitments.
- The Core Gameplay Loop document, which describes the central gameplay cycle.
- Art and Audio Direction documents, which define visual and audio identity.
- Narrative Design documents, which define the story and narrative systems.
- Production plans, which define schedules, milestones, and development tasks.

## 1.3 Document Authority

The approved Game Vision is a foundational reference for the project.

Major creative and design decisions should be evaluated against it.

Changes to the vision may affect the game's identity, audience, scope, and production direction. Significant changes require project owner approval.

# 14. AI-Assisted Development Guidelines

AI tools may assist with concept exploration, design analysis, documentation, prototyping, and development planning.

AI agents must follow these rules:

1. Read this document before proposing significant creative or design changes.
2. Treat the approved vision as a foundational project constraint.
3. Preserve the intended player experience when suggesting features.
4. Evaluate major proposals against the game's identity and creative priorities.
5. Do not replace the established vision with generic genre conventions.
6. Distinguish approved decisions from ideas and assumptions.
7. Identify conflicts between proposed features and the vision.
8. Avoid expanding scope without a clear contribution to the intended experience.
9. Do not invent creative decisions and present them as approved.
10. Never modify or approve the vision without project owner authorization.

When information is missing, identify the uncertainty and request clarification when it materially affects the task.

# 17. Document Maintenance

Review this document when:

- The game's central concept changes.
- The target audience changes significantly.
- The intended player experience changes.
- The game's identity or creative direction is redefined.
- Major production constraints require a fundamental creative adjustment.
- Playtesting reveals that the current vision is not achievable or does not produce the intended experience.

Changes to the Game Vision should be deliberate and approved by the project owner.

Preserve the reasoning behind significant changes and update affected design documents to maintain consistency.

The Game Vision should remain concise, understandable, and useful as a decision-making reference throughout development.
