# Visual Consistency Guidelines

## 1. Purpose

This document defines guidelines for maintaining a coherent and recognizable visual identity throughout a game.

Its purpose is to ensure that visual elements work together rather than appearing as unrelated assets created independently.

Visual consistency helps establish:

- A recognizable artistic identity.
- A coherent game world.
- Clear visual communication.
- Consistent player expectations.
- Readable gameplay elements.
- A professional and cohesive presentation.

These guidelines are reusable across studio projects. Each game MUST establish its own visual direction, artistic references, stylistic characteristics, and project-specific visual rules.

## 2. Scope

These guidelines apply to all visual elements, including:

- Characters and creatures.
- Environments and locations.
- Props and interactive objects.
- Architecture and structures.
- Materials and textures.
- Lighting and shading.
- Color palettes.
- Visual effects.
- Animations.
- User interfaces.
- Icons and illustrations.
- Typography used in visual compositions.
- Cinematic and promotional assets.

These guidelines focus on visual coherence across the game.

Specific asset quality requirements are defined in `ART_ASSET_STANDARDS.md`. Interface-specific requirements are defined in `UI_UX_STANDARDS.md`. Animation requirements are defined in `ANIMATION_STANDARDS.md`.

## 3. Core Principles

### 3.1. Coherent Visual Identity

All visual elements SHOULD contribute to the same overall artistic identity.

Individual assets MAY have different visual characteristics when justified by their purpose, origin, or context, but they SHOULD still feel like parts of the same game.

### 3.2. Intentional Variation

Consistency does not mean making every asset identical.

Variation SHOULD support:

- Environmental diversity.
- Character identity.
- Gameplay readability.
- Narrative meaning.
- Visual interest.
- Recognition of different categories and factions.

Variation MUST remain within the established visual direction unless an intentional stylistic contrast is required.

### 3.3. Gameplay Readability

Visual consistency MUST NOT compromise gameplay clarity.

Important gameplay elements SHOULD remain distinguishable from decorative elements and background details.

Players SHOULD be able to recognize relevant objects, characters, hazards, and interactions without unnecessary visual effort.

### 3.4. Contextual Consistency

Visual elements SHOULD make sense within their environment and narrative context.

Consider:

- Location.
- Historical or fictional setting.
- Culture and factions.
- Materials and construction methods.
- Technology level.
- Environmental conditions.
- Gameplay purpose.

### 3.5. Reusable Visual Rules

Projects SHOULD define reusable visual rules rather than relying exclusively on individual artistic judgment.

These rules SHOULD be documented sufficiently for artists and AI agents to produce compatible assets.

## 4. Visual Direction

Each game project MUST establish an approved visual direction before large-scale asset production.

The visual direction SHOULD describe:

- Overall artistic identity.
- Intended mood and atmosphere.
- Realism or stylization level.
- Shape language.
- Color philosophy.
- Lighting approach.
- Material treatment.
- Detail density.
- Proportions and scale.
- Environmental characteristics.
- Character design conventions.
- Visual references.
- Deliberate stylistic exceptions.

### 4.1. Visual Reference Library

Projects SHOULD maintain a curated collection of visual references.

References MAY include:

- Concept art.
- Photography.
- Architecture.
- Historical objects.
- Materials.
- Color studies.
- Character designs.
- Environmental compositions.
- Lighting examples.
- Existing game references.

Each reference SHOULD communicate a specific visual characteristic or design intention.

References MUST NOT be treated as unrestricted instructions to reproduce copyrighted artwork or another game's distinctive assets.

### 4.2. Visual Direction Authority

The approved project visual direction is the primary reference for visual consistency.

When an asset conflicts with established direction, it SHOULD be revised or the relevant visual direction decision should be reviewed.

AI agents MUST NOT independently redefine the game's visual identity.

## 5. Shape Language and Proportions

Shape language contributes significantly to visual recognition and identity.

### 5.1. Shape Language

Projects SHOULD define appropriate shape conventions for important visual categories.

Examples include:

- Rounded shapes for friendly or approachable elements.
- Angular shapes for aggressive or mechanical elements.
- Organic shapes for natural environments.
- Geometric shapes for constructed or technological elements.

These are design possibilities, not universal rules.

Shape choices MUST be appropriate to the project's visual direction.

### 5.2. Proportions

Related assets SHOULD maintain compatible proportions.

Consider:

- Character proportions.
- Object dimensions.
- Architectural scale.
- Environmental features.
- Equipment size.
- Relative object dimensions.

Significant proportional differences SHOULD have a clear artistic or gameplay justification.

### 5.3. Silhouette Recognition

Important characters, objects, and gameplay elements SHOULD have recognizable silhouettes.

Evaluate silhouettes without relying exclusively on internal details, textures, or colors.

This is particularly important for gameplay-critical entities and objects.

## 6. Color Consistency

Color SHOULD reinforce the visual identity and help communicate relationships between visual elements.

### 6.1. Color Palette

Each project SHOULD define a documented color palette.

It MAY include:

- Primary colors.
- Secondary colors.
- Accent colors.
- Environmental colors.
- Character and faction colors.
- Material colors.
- Lighting colors.
- Gameplay indicator colors.

### 6.2. Color Relationships

Colors SHOULD work together across characters, environments, props, and effects.

Avoid introducing colors that conflict with the established palette without a deliberate reason.

### 6.3. Contextual Color Variation

Color variation MAY communicate:

- Different environments.
- Time of day.
- Weather.
- Factions.
- Object conditions.
- Gameplay states.
- Narrative significance.

Variations SHOULD preserve the overall visual identity.

### 6.4. Color and Gameplay

Important gameplay information SHOULD remain distinguishable from environmental decoration.

Do not rely exclusively on color to communicate critical gameplay information.

## 7. Lighting and Shading

Lighting and shading SHOULD follow a coherent visual approach.

Projects SHOULD define conventions for:

- Light direction.
- Light intensity.
- Ambient lighting.
- Shadow softness.
- Contrast.
- Highlight treatment.
- Material response.
- Atmospheric effects.
- Environmental lighting variation.

### 7.1. Lighting Consistency

Related environments and assets SHOULD use compatible lighting assumptions.

Lighting differences MAY be introduced to communicate different locations, moods, or gameplay situations.

### 7.2. Material Response

Materials SHOULD react to lighting in ways consistent with their intended appearance and the project's rendering approach.

Avoid inconsistent shading or material treatment between assets that belong to the same visual category.

### 7.3. Visual Readability

Lighting MUST preserve the readability of important characters, objects, and gameplay elements.

Artistic lighting effects SHOULD NOT unnecessarily obscure essential information.

## 8. Materials and Textures

Materials and textures SHOULD maintain a consistent level of visual detail and treatment.

### 8.1. Material Style

Projects SHOULD define conventions for:

- Surface roughness.
- Reflectivity.
- Transparency.
- Texture detail.
- Surface imperfections.
- Wear and damage.
- Stylization.
- Shading complexity.

### 8.2. Texture Consistency

Related assets SHOULD use compatible texture resolution, detail density, and visual treatment.

Avoid mixing highly detailed textures with extremely simplified textures without a deliberate stylistic reason.

### 8.3. Surface Variation

Variation in wear, dirt, damage, and aging SHOULD support the environment and object's context.

Surface details SHOULD communicate useful visual information rather than exist solely as decoration.

## 9. Detail Density and Visual Complexity

Visual complexity SHOULD be distributed intentionally.

### 9.1. Detail Hierarchy

Projects SHOULD establish appropriate detail levels for:

- Primary characters and objects.
- Secondary characters and objects.
- Environmental structures.
- Background elements.
- Decorative assets.
- Gameplay indicators.

Important elements MAY receive greater detail when it supports their visual or gameplay purpose.

### 9.2. Detail Consistency

Assets occupying similar visual roles SHOULD maintain compatible detail density.

Avoid situations where one asset appears substantially more realistic, polished, or detailed than surrounding assets without justification.

### 9.3. Distance and Scale

Detail SHOULD remain appropriate for the intended viewing distance.

Assets MUST be evaluated in their actual gameplay context, not exclusively in close-up previews.

## 10. Environment and World Consistency

Environments SHOULD communicate a coherent world through architecture, materials, objects, lighting, and composition.

### 10.1. Environmental Identity

Each environment SHOULD have identifiable visual characteristics.

These MAY include:

- Architecture.
- Terrain.
- Vegetation.
- Materials.
- Color palette.
- Weather.
- Lighting.
- Decorative objects.
- Environmental storytelling.

### 10.2. Environmental Cohesion

Objects placed within an environment SHOULD appear appropriate to that location.

Consider their:

- Construction materials.
- Age and condition.
- Scale.
- Purpose.
- Cultural context.
- Relationship to surrounding structures.

### 10.3. Repeated Elements

Repeated environmental elements SHOULD maintain consistent design characteristics while allowing appropriate variation.

Examples include:

- Building components.
- Furniture.
- Vegetation.
- Rocks.
- Street objects.
- Architectural details.

Avoid obvious repetition when it negatively affects visual quality.

### 10.4. Environmental Storytelling

Visual details SHOULD support the intended history, atmosphere, and identity of an environment.

Objects, damage, materials, and spatial arrangements SHOULD feel intentional rather than randomly assembled.

## 11. Character and Creature Consistency

Characters and creatures SHOULD follow coherent visual design conventions.

### 11.1. Character Identity

Character designs SHOULD communicate their identity through appropriate combinations of:

- Silhouette.
- Proportions.
- Clothing.
- Equipment.
- Materials.
- Color.
- Accessories.
- Animation style.

### 11.2. Shared Design Conventions

Characters belonging to the same faction, group, culture, or species SHOULD share recognizable visual characteristics where appropriate.

Individual differences SHOULD preserve their identity and avoid unnecessary uniformity.

### 11.3. Equipment and Accessories

Equipment SHOULD be visually compatible with its character and the game's world.

Consider scale, materials, construction, and stylistic treatment.

### 11.4. Character Readability

Characters SHOULD remain recognizable in their intended gameplay environments.

Important characters SHOULD be distinguishable from background elements and other entities.

## 12. Props and Interactive Objects

Props SHOULD follow the visual conventions of their environment and intended function.

### 12.1. Functional Appearance

Objects SHOULD communicate their intended purpose through their appearance when practical.

Interactive objects SHOULD be distinguishable when their gameplay role requires it.

### 12.2. Shared Categories

Related objects SHOULD share appropriate visual characteristics.

Examples include:

- Tools.
- Weapons.
- Containers.
- Furniture.
- Collectibles.
- Machinery.
- Environmental objects.

### 12.3. State Representation

When an object's state changes, its visual representation SHOULD communicate the change clearly.

Examples include:

- Damaged objects.
- Open or closed containers.
- Activated mechanisms.
- Depleted resources.
- Interactable objects.
- Equipped or unequipped equipment.

## 13. Visual Effects Consistency

Visual effects SHOULD follow the game's established visual identity.

Projects SHOULD define conventions for:

- Particle appearance.
- Shape and motion.
- Color.
- Opacity.
- Intensity.
- Duration.
- Lighting contribution.
- Material treatment.
- Screen-space effects.

### 13.1. Gameplay Effects

Gameplay-critical effects MUST communicate their purpose clearly.

Examples include:

- Damage.
- Healing.
- Status effects.
- Explosions.
- Environmental hazards.
- Interaction feedback.
- Ability activation.

### 13.2. Effect Hierarchy

Effects SHOULD have appropriate visual intensity relative to their importance.

Avoid allowing decorative effects to compete with critical gameplay feedback.

### 13.3. Effect Consistency

Related effects SHOULD share compatible visual conventions.

Different effect categories MAY have distinct visual identities when this improves recognition.

## 14. Animation Consistency

Animations SHOULD maintain compatible movement, timing, and presentation conventions.

Consider:

- Character movement style.
- Object motion.
- Animation timing.
- Anticipation.
- Follow-through.
- Transition behavior.
- Visual exaggeration.
- Animation smoothness.

Related entities SHOULD have compatible animation characteristics unless their design requires deliberate differences.

Animation-specific production and implementation requirements are defined in `ANIMATION_STANDARDS.md`.

## 15. UI and World Visual Consistency

The interface SHOULD feel like a deliberate part of the game's visual identity.

UI elements MAY use a different visual treatment from the game world when required for readability and usability.

However, their design SHOULD remain compatible with the overall artistic direction.

Consider:

- Color palette.
- Typography.
- Icon style.
- Shape language.
- Materials and textures.
- Borders and panels.
- Animation.
- Visual effects.

Gameplay readability and interface usability MUST take priority over decorative stylistic consistency.

Detailed interface requirements are defined in `UI_UX_STANDARDS.md`.

## 16. Asset Integration and Visual Validation

Assets MUST be evaluated in the context in which they will appear.

A visually acceptable standalone asset is not necessarily visually consistent with the game.

### 16.1. Integration Review

Review assets alongside relevant existing content.

Consider:

- Neighboring assets.
- Environment lighting.
- Camera distance.
- Display scale.
- Color relationships.
- Material appearance.
- Detail density.
- Gameplay visibility.
- Animation and effects.
- Interface presentation, when applicable.

### 16.2. Visual Comparison

Use approved references and existing assets to identify inconsistencies.

Comparison SHOULD focus on meaningful characteristics rather than requiring exact visual duplication.

### 16.3. Validation Outcomes

Visual reviews SHOULD produce one of the following outcomes:

- **Accepted:** The asset follows the established visual direction and is suitable for integration.
- **Changes Required:** The asset has correct overall intent but needs visual adjustments.
- **Blocked:** Required references, decisions, or dependencies are missing.
- **Rejected:** The asset fundamentally conflicts with the approved visual direction or requirements.

### 16.4. Visual Regression

When modifying shared visual elements or established styles, review affected areas for unintended inconsistencies.

Changes to shared palettes, materials, lighting conventions, or reusable components SHOULD be evaluated across representative content.

## 17. Visual Documentation

Each project SHOULD maintain enough visual documentation to communicate its artistic identity and support consistent production.

Depending on project scope, documentation MAY include:

- Art direction document.
- Visual reference library.
- Color palette.
- Shape language references.
- Character style guide.
- Environment style guide.
- Material and texture references.
- Lighting references.
- UI visual design system.
- Visual effects references.
- Approved asset examples.

Documentation SHOULD be practical, current, and easy for contributors to follow.

Avoid duplicating the same visual rules across multiple documents. Maintain a clear authoritative source for each decision.

## 18. AI-Assisted Visual Production

AI agents MAY assist with concept exploration, reference analysis, asset generation, visual review, and consistency checks.

AI-assisted work MUST follow the approved project visual direction.

Agents SHOULD:

1. Review relevant visual standards and references before generating or modifying assets.
2. Identify the intended asset category and visual role.
3. Preserve established proportions, palettes, materials, and detail conventions.
4. Compare proposed assets with existing approved content.
5. Identify meaningful visual deviations.
6. Validate assets in their intended gameplay context when possible.
7. Report unresolved inconsistencies and technical limitations.
8. Request approval before changing established visual direction.

AI agents MUST NOT:

- Introduce unrelated visual styles without approval.
- Treat generated assets as automatically compliant.
- Replace approved visual references without authorization.
- Claim visual validation was performed when it was not.
- Ignore licensing, attribution, or source asset requirements.
- Independently approve significant changes to the project's visual identity.

## 19. Visual Consistency Review Checklist

Before accepting new or modified visual content, verify the applicable requirements:

- [ ] The asset follows the approved visual direction.
- [ ] Its shape language and proportions are appropriate.
- [ ] Its color treatment is consistent.
- [ ] Lighting and shading are compatible.
- [ ] Materials and textures use appropriate detail.
- [ ] Detail density matches its intended visual role.
- [ ] It fits its environment and narrative context.
- [ ] Its silhouette and purpose are recognizable.
- [ ] Gameplay-critical information remains readable.
- [ ] Animation and effects are visually compatible.
- [ ] UI elements follow the established interface style.
- [ ] The asset looks appropriate in its actual gameplay context.
- [ ] Relevant visual references have been followed.
- [ ] Any stylistic deviation has a clear justification.
- [ ] Required documentation has been updated.

Not every item applies to every asset. Non-applicable requirements SHOULD be identified rather than treated as failures.

## 20. Exceptions

Exceptions MAY be appropriate when required by:

- Gameplay readability.
- Narrative significance.
- Environmental context.
- Deliberate artistic contrast.
- Accessibility.
- Technical limitations.
- Platform requirements.
- Experimental visual direction.

Exceptions SHOULD have a clear purpose and remain limited to their intended context.

Changes that redefine the project's established visual identity MUST receive project owner approval.

Significant or long-term changes SHOULD be documented in the relevant project documentation.

## 22. Maintenance

These guidelines SHOULD be reviewed periodically and updated when:

- The studio's visual production practices change.
- New visual styles or production techniques are adopted.
- Recurring visual consistency problems are identified.
- Engine capabilities or rendering requirements change.
- Accessibility requirements evolve.
- Improvements to visual review and validation practices are identified.

Changes MUST preserve the distinction between reusable studio guidelines and project-specific artistic decisions.

The project owner is responsible for approving changes to these guidelines.
